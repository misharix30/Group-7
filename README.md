# اعرف دوائك

تطبيق محلي بواجهة شات لفحص التداخلات بين دواءين، مكتوب ببايثون وStreamlit مع CSS بسيط. يعرض أحدث سؤال وإجابته فقط، ويزيلهما عند إرسال سؤال جديد. لا يكتب محادثات المستخدم إلى ملفات أو قاعدة بيانات؛ يحتفظ فقط بالطلب الحالي في ذاكرة الجلسة لعرضه. لا تُرسل الأسئلة السابقة إلى النماذج.

## الهيكلة

```text
project/
├── README.md
├── requirements.txt
├── testing_data/                   # أسئلة النوتبوك واختبارات نقل النظام
├── notebooks/                      # النوتبوكات الأصلية دون تغيير محتواها
├── src/                            # التحميل، البرومبتات، الاسترجاع، المعالجة والعرض
├── app.py
├── results/                        # تقارير البيئة والتحقق، وليس أوزان النماذج
├── ddi_cleaned.csv                 # البيانات الأصلية في موقعها
├── ddi_chroma_db_backup/
│   └── ddi_chroma_db/
│       └── chroma.sqlite3
├── .venv/                          # بيئة المشروع المستقلة، مستبعدة من Git
└── .streamlit/config.toml          # واجهة فاتحة وتشغيل محلي فقط
```

## البيئة والتشغيل على Windows

البيئة مجهّزة باستخدام Python 3.11.9. `requirements.txt` يحدد المكتبات المطلوبة، مع نسخة PyTorch CUDA 12.8 وtorchvision المطابقة. بيانات فحص البيئة والإصدارات الفعلية محفوظة في `results/`.

من جذر المشروع، لا تحتاج إلى تفعيل البيئة إذا استخدمت مسار Python المباشر:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

افتح `http://localhost:8501` في المتصفح. تُحمَّل النماذج عند إرسال السؤال الأول، ثم تُعاد الاستفادة منها بين الطلبات. الواجهة تعطل الإرسال أثناء العمل، وتعالج المدخل الفارغ قبل تحميل النماذج.

إذا أردت تفعيل البيئة:

```powershell
.\.venv\Scripts\Activate.ps1
```

إذا منع PowerShell التفعيل، استخدم مسار Python المباشر أعلاه؛ لا يلزم تغيير سياسة الجهاز.

لإعادة إنشاء البيئة على جهاز Windows آخر لديه NVIDIA:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## صلاحية الوصول إلى النماذج

يتطلب MedGemma قبول شروط النموذج في [Hugging Face](https://huggingface.co/google/medgemma-1.5-4b-it) وصلاحية تنزيله. استخدم متغير البيئة `HF_TOKEN` أو تسجيل الدخول إلى Hugging Face مسبقًا. لا تضع الرمز في الكود أو المستودع. مثال لإدخاله مخفيًا في جلسة PowerShell الحالية:

```powershell
$env:HF_TOKEN = [System.Net.NetworkCredential]::new('', (Read-Host 'Hugging Face token' -AsSecureString)).Password
.\.venv\Scripts\python.exe -m streamlit run app.py
```

التنزيل الأول قد يستغرق وقتًا ومساحة قرص إضافية. يستخدم التطبيق مخزن Hugging Face المحلي المعتاد، ولا ينسخ أوزان النماذج إلى `results/`.

أغلق kernel النوتبوك الذي حمّل النموذجين قبل إرسال سؤال للتطبيق. البطاقة الحالية لديها نحو 8GB VRAM، وتشغيل نسخة أخرى من النموذجين يستهلك الذاكرة اللازمة. يتحقق التطبيق من CUDA ومن توفر 6GiB على الأقل قبل بدء التحميل؛ هذه عتبة تجهيز وليست ضمانًا لكفاية الذاكرة أثناء التوليد. يستخدم قفلًا مشتركًا لمنع التوليد المتزامن بين جلسات التطبيق في العملية الواحدة.

## النماذج ومسار الطلب

- `Qwen/Qwen3-4B-Instruct-2507`: تصنيف السؤال واستخراج التفاعل، باستدعاء واحد.
- `google/medgemma-1.5-4b-it`: شرح التفاعل المطابق بلغة سؤال المستخدم.
- `BAAI/bge-small-en-v1.5`: تضمين السؤال على CUDA، مع التطبيع و`batch_size=128`.
- المجموعة المحفوظة `ddi_interactions`، باستخدام `k=1`.

البرومبتات في `src/prompts.py` ودوال التوليد في `src/generation.py` منقولة حرفيًا من النسخة المعدّلة من `Prompt_Engineering_with_RAG_Organized.ipynb`. النموذجان يستخدمان NF4 من نوع 4-bit و`bfloat16` و`device_map="auto"` كما في النوتبوك.

Qwen يستخدم `max_new_tokens=256` و`do_sample=False`. MedGemma يستخدم `max_new_tokens=2000` و`do_sample=True` و`temperature=0.9` و`top_p=0.7`، مع إخفاء التفكير الداخلي. لذلك يمكن أن تختلف صياغة الشرح بين التشغيلات. توجيه 80 كلمة محفوظ في البرومبت، ولا يوجد قص برمجي للإجابة.

يسترجع التطبيق سجلًا واحدًا مرة واحدة ويحتفظ به طوال الطلب. يستدعي MedGemma فقط إذا كانت الحالة `valid` وكان رد Qwen مساويًا حرفيًا لتفاعل نفس السجل. تُعرض رسائل Qwen الأخرى مباشرة دون ترجمة أو إعادة صياغة. يُرسل إلى MedGemma سؤال الطلب الحالي والتفاعل فقط. لا تُعاد عملية الاسترجاع للمقارنة، ولا تُنظَّف البيانات أو يُعاد بناء المجموعة.

تُعرض العربية باتجاه RTL والإنجليزية باتجاه LTR. يظهر قسم اختياري للتفاعل الأصلي ومصدره ورقم السجل فقط عند استخراج تفاعل مطابق. عدم العثور على سجل مطابق لا يعني عدم وجود تداخل أو أن الجمع بين الدواءين آمن.

يستخدم `src/output_parser.py` محلّل النوتبوك المعتاد أولًا. إذا فشل بسبب اقتباسات غير مهرّبة داخل `response`، يعالج هذا التنسيق فقط في رد مكتمل ذي الحقلين المعروفين، دون تغيير نص الإجابة أو الحالة. تُرفض البنية الملتبسة والحقول الإضافية، ويظل شرط المطابقة الحرفية محفوظًا. لا يعيد هذا الإصلاح استدعاء Qwen أو الاسترجاع، ولا يغيّر البرومبتات أو إعدادات التوليد.

## النوتبوكات

نُقلت النوتبوكات إلى `notebooks/` مع الحفاظ على محتواها ومخرجاتها. استخدم interpreter الموجود في `.venv/Scripts/python.exe` في محررك. JupyterLab وipykernel مثبتان في البيئة نفسها، ويمكن تشغيلهما باستخدام:

```powershell
.\.venv\Scripts\python.exe -m jupyterlab
```

النوتبوكات الأصلية تستخدم مسارات بيانات نسبية إلى جذر المشروع؛ يجب أن يكون مجلد عمل kernel هو جذر المشروع عند تشغيلها. التطبيق نفسه يبني جميع مساراته من جذر المشروع تلقائيًا.

عند فتح Chroma على Windows داخل مسار يحتوي أحرفًا عربية، يثبّت التطبيق مجلد عمل العملية على جذر المشروع ويمرّر مسار القاعدة النسبي كما في النوتبوك. هذا يتجاوز فشل فتح HNSW بالمسار المطلق، دون نقل البيانات أو إعادة بناء الفهرس، ويعمل أيضًا عند إطلاق التطبيق من مجلد آخر.

تم تسجيل kernel باسم **اعرف دوائك (.venv)** داخل البيئة نفسها، دون تغيير بيئة Python العامة.

## التحقق

```powershell
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m src.check_environment
.\.venv\Scripts\python.exe -m pytest testing_data -q
```

لاختبار النموذجين فعليًا باستخدام الأوزان المحلية فقط، أغلق جلسات النوتبوك والتطبيق التي حمّلت النماذج أولًا، ثم نفّذ:

```powershell
.\.venv\Scripts\python.exe -m testing_data.live_smoke --offline
```

هذا الاختبار يحفظ حالات النجاح وعدد الكلمات فقط في `results/live_smoke.json`، دون حفظ نصوص الإجابات. احذف `--offline` إذا كانت ملفات النماذج لم تُحمّل مسبقًا وتوفرت صلاحية الوصول.

اختبارات نقل النظام تستخدم استجابات مضبوطة للتحقق من استدعاء MedGemma، وعدم استدعائه للرسائل الأخرى، وتمرير السؤال الحالي بالعربية والإنجليزية، والاسترجاع مرة واحدة والمطابقة الحرفية. اختبارات الواجهة تتحقق من استبدال الرسالة السابقة ورفض المدخل الفارغ. اختبارات المرجع تتحقق من تطابق البرومبتات ودوال التوليد وحفظ محتوى النوتبوكات والـCSV.

هذه الاختبارات لا تقيس دقة النماذج الفعلية. توضح `results/validation.md` ما جرى تشغيله فعليًا وما تعذر اختباره. النتائج القديمة، 95% لتصنيف 20 سؤالًا و100% للاستخراج في عينة من 20 صفًا، تخص النسخة والتقييم المحفوظين ولا تمثل ضمانًا أو نتيجة جديدة للبرومبت المعدّل. حالة قبول سؤال ناقص المسجلة سابقًا تحتاج إلى إعادة تقييم بعد تعديلك؛ لا يوجد تعديل إضافي للبرومبتات في التطبيق.

تفاصيل الأخطاء تظهر في نافذة تشغيل التطبيق فقط. لا تُفعَّل خدمات تتبع الأسئلة، ولا تُحفظ سجلات المحادثات.
